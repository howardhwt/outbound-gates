# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Primary: GTM engineers who already work in Claude Code and let an agent draft outbound. They arrive from the GitHub README, a LinkedIn post or Howard's portfolio, and want to see the gate catch an unsourced number, then install the plugin and run `/outbound-gates:start` on their own prospect.

Secondary: founders and hiring managers skimming the repo as proof that Howard builds the systems he sells with. The portfolio's case study makes the hiring case; this site does not need to.

## Product Purpose

outbound-gates is an open-source Claude Code plugin that wraps the steps around a cold email (source, qualify, draft, gate, pre-send, log). Its core promise: the agent can't put an unsourced number in a cold email, and it can't send. A person sends.

The site (howardhwt.github.io/outbound-gates) shows that promise working, step by step, from a real gate run: blocked, source recorded, passed. Success is a GTM engineer installing the plugin and getting their first catch with `/outbound-gates:start`.

## Positioning

The gate checks every number in a draft against the exact sentence on the company's own site, a calculation it recomputes, or one of your own facts, and it does this when the draft is created. The guardrail tools reviewed (HarnessGuard, GouvernAI, AI SDR guardrail guides) don't. Send, reply and forward are blocked at the tool level, not by instruction.

## Operating Context

- Visitors read the page on desktop next to a terminal, often coming straight from the README's clip.
- The next step is always in a terminal: `/plugin install`, then `/outbound-gates:start` or `/outbound-gates:try`.
- Pages: `index.html` (the catch replay) and `pipeline.html` (the full demo pipeline report).

## Capabilities and Constraints

- The site is generated by `python -m demo.site` from real gate runs and deployed by `.github/workflows/pages.yml` to GitHub Pages. No hand-written run output; `tests/test_site.py` fails if the page stops showing blocked, recorded, passed in order, or if build-machine paths leak.
- `docs/catch.svg` (the README clip) comes from the same run and must equal a fresh build.
- Static HTML and CSS only, no build tooling beyond the Python generator, no runtime dependencies.
- Decided: the site feels like one universal site with howardhwt.github.io. It carries the portfolio's floating pill nav with a short link list ("Howard Tam" home, Work, outbound-gates as current, GitHub), not a full copy of the portfolio nav, so the copy in this repo rarely drifts. A test checks the links point at real portfolio paths.

## Brand Commitments

- Visual authority is the portfolio's design system: `howardhwt.github.io/DESIGN.md` and `.impeccable/design.json` ("The Instrument Panel": monochrome graphite, Geist and Geist Mono, hairlines, flat, emphasis by luminance, no red or green for state). This site should feel like part of the same site, not a separate brand.
- Name: `outbound-gates`, lowercase, in code style where it is a command or repo.
- Voice: plain, specific, first-hand. Every number has a source; illustrations are labelled; limits are stated.
- Glossary terms (`GLOSSARY.md`): send gate, try folder, first catch, own facts, logging BCC.

## Evidence on Hand

- Real gate runs on the bundled demo company (fictional product Acme Transcribe; fictional companies such as Northwind Audio). Clip: `docs/catch.svg`. Pipeline demo: `docs/demo.gif`, `docs/report.png`, `pipeline.html`.
- Docs: `docs/quickstart.md`, `docs/send-gate.md`, `docs/adr/0001-approval-by-code.md`.
- Absent and must not be fabricated: real prospects, real customer names, user counts, testimonials, star counts. The repo is public; no real company, contact or CRM id appears anywhere on the site.

## Product Principles

1. Show the catch, don't describe it: the first screen is a real blocked, recorded, passed run.
2. The next step is a command: every page ends at install and `/outbound-gates:start`.
3. Generated, never pasted: what the page shows is what the gate printed today.
4. One site with the portfolio: same look and voice, so a visitor never feels they left Howard's site.
5. Honest edges: label demos as demos, say what is fictional, say what the gate does not check.

## Accessibility & Inclusion

Inherit the portfolio's floor: skip link and main landmark, 44px minimum hit areas, visible focus, reduced-motion and no-script fallbacks for the replay, readable in print.
